Worked Examples: Inputs & Outputs

The method for every problem type on the sheet, worked on a twin problem so you can copy the moves onto your own numbers.

The one big idea

A function is an input → output machine. f(20) means: put 20 into machine f, and read what comes out.

Every problem here is a version of that. Keep asking yourself two questions: What's the input? What's the output? Almost every mistake at this level comes from mixing those two up.

Type 1 · read a graph

Given the input → find the output

On a graph (like the dog's distance vs. time), f(20) means input = 20 on the bottom axis.

  1. Find the input (20) on the bottom axis.
  2. Go straight up to the curve.
  3. Go straight across to the side axis — that height is the output.

Twin example

To find f(60): find 60 on the bottom, go up to the curve, read across — say it sits at 5. → f(60) = 5
Your turn: do this for f(20) and f(140) on your graph.
Type 2 · run it backwards

Given the output → find the input

“When is f(x) = 3?” gives you the output (3) and asks for every input that produces it.

  1. Find the output (3) on the side axis.
  2. Draw a horizontal line across.
  3. Mark every place the curve touches that line; read those inputs off the bottom.
Expect more than one answer. Running the machine backwards can land on several inputs — list all of them.
Your turn: find every time where f(x) = 3.
Type 3 · evaluate with algebra

Plug the input into a formula

Same “input → output,” but with a rule instead of a graph. Wherever you see x, substitute the input in parentheses, then do order of operations: exponent first, then multiply, then add.

Twin example — f(x) = −2x2 − 4x + 5, find f(3)

f(3) = −2(3)2 − 4(3) + 5 = −2(9) − 12 + 5 ← square first: 32 = 9 = −18 − 12 + 5 → f(3) = −25
The parentheses protect you. A negative input must be squared inside its parentheses: (−3)2 = 9, but −32 = −9. Different answers.
Your turn: do f(0) and f(7) the same way. Watch the signs — negatives are where points get lost. (There's a draggable version of this in your lesson.)
Type 3b · solve for the input

Output given → undo it step by step

e.g. n(x) = 6x + 12 and n(x) = 42. The output (42) is given; find the input. Set the rule equal to the output and peel operations off — last one first.

Twin example — m(x) = 4x + 5, when m(x) = 25

4x + 5 = 25 4x = 20 ← undo + 5 (subtract 5 both sides) x = 5 ← undo × 4 (divide both sides by 4)
Your turn: solve 6x + 12 = 42 and 8x − 3 = 45. Check by plugging your x back in — it should give the target output.
Type 4 · domain, range, is-it-a-function

Inputs, outputs, and the one-output rule

Domain = all the inputs (x-values, read left→right). Range = all the outputs (y-values, read bottom→top).

It's a function only if each input has exactly one output.

  1. On a graph: the vertical-line test — if any vertical line hits the curve more than once, it's not a function.
  2. On a mapping diagram (ovals with arrows): follow each input arrow. If one input points to two outputs, it's not a function.

Twin example

Inputs {1, 2, 3}, and 2 has arrows to BOTH 5 and 8 → not a function (input 2 gives two outputs)
Two inputs sharing one output is fine. One input with two outputs is not.
Your turn: for each graph and the oval diagram — state the domain, state the range, then apply the one-output test.
Type 5 · solve equations

Simplify, then undo

Same skill as “solve for the input,” just longer. Only two moves: (1) simplify each side (distribute, combine like terms), then (2) undo to isolate the variable, doing the same to both sides.

Twin example

30 = 5(d − 2) − 5 30 = 5d − 10 − 5 ← distribute the 5 30 = 5d − 15 ← combine −10 and −5 45 = 5d ← undo − 15 (add 15) → d = 9

Another — combine like terms first

2n − 5n + 3 = −3 −3n + 3 = −3 ← combine 2n and −5n −3n = −6 ← undo + 3 → n = 2
Your turn: for each equation, first ask “what's cluttering this side?” — distribute and combine before you undo. Then undo in reverse order of operations.
Stuck? Ask yourself: What's the input, what's the output? Am I given the input and finding the output, or the other way round? What can I simplify first? Did I put the input in parentheses before squaring?
